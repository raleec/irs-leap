51 - EXPRESSIONS KEYED BY EXACT ACTION NAME

Paste expressions through fx, WITHOUT @ or @{...}. Constant text is entered as
text, not as an expression. Use exactly the names/tree in 50. Connector output
paths below are the common Standard approvals/Dataverse paths; inspect the
synthetic run's raw output and record a verified equivalent if the tenant differs.
Do not guess an absent ID/outcome, or convert a missing outcome to Reject.
Get row/List rows return Web API lookup fields, not Canvas record structures.

Filter_ValidApproverUsers -> From:

Predicate:

  contains(outputs('Compose_SelectedApproverGuids'), toLower(string(item()?['systemuserid']))),
  equals(item()?['isdisabled'], false),
  equals(item()?['accessmode'], 0),
  empty(item()?['applicationid']),

Condition_RecoveryNeeded
Scope_Recovery runs after Scope_Notify for all statuses. Predicate:
or(
  not(empty(variables('varIssue'))),
  and(
    not(equals(actions('Scope_Process')?['status'], 'Succeeded')),
    not(
      and(
        equals(actions('Update_Expired')?['status'], 'Succeeded'),
        equals(actions('Set_Terminal_Expired')?['status'], 'Succeeded')
      )
    )
  ),
  equals(actions('Scope_Notify')?['status'], 'Failed'),
  equals(actions('Scope_Notify')?['status'], 'TimedOut')
)
A handled Wait timeout followed by successful Update_Expired and
Set_Terminal_Expired is expected; do
not turn it into a processing failure just because a containing scope reports a
timed-out child. Its notification failure still routes to recovery. All other
unexpected Process failures/timeouts, including a decision write failure, alert.

NO HIDDEN EXPRESSIONS
Scope_Process, Scope_AwaitDecision, Scope_Expire, Scope_Notify, Scope_Recovery
are Control > Scope containers, with run-after configured by 52, not expressions.
All unstated run-after settings are predecessor SUCCEEDED only. Do not broaden
Wait downstream paths to skipped/failed. If an action is absent from the tree,
do not paste an expression referencing it and assume the designer will create it.
