-------------------------------
The source delivery includes scripts\auth.py, copied from the documented
Dataverse helper and scoped to this project. It does not include the previous
user's token cache, account record, tenant configuration, password or .env.

Create a local .env in this directory (do not commit/share it) containing:

DATAVERSE_URL=https://YOUR-APPROVED-ORG.crm9.dynamics.com
TENANT_ID=YOUR-APPROVED-TENANT-GUID

For a commercial sandbox, use its actual hostname instead. The example is NOT
an instruction to change clouds or infer an organization from a guessed name.
GCC uses public Entra identity; GCC High/DoD authentication is outside this
source candidate and requires the agency's supported government configuration.

The auth helper searches its parent directory and the current directory.
It opens a device-code sign-in and caches tokens in the OS-protected credential
store. Enter credentials only on Microsoft's sign-in page. Its authentication
record .auth_record.json is not a source/distribution artifact.

Verify target and account before any changes:

pac auth create --name IRSLEAPWorkshop --environment https://YOUR-APPROVED-ORG.crm9.dynamics.com --cloud UsGov

For commercial development use --cloud Public instead. Verify the output URL,
tenant and user match the approved deployment exactly. Authentication/role
assignment is not supplied by the starter, and no script grants an admin role.

SECURITY AND CONCURRENCY LIMITATIONS
----------------------------------
Participants use Basic User plus IRS LEAP Participant; native request records
are private except explicitly shared Read access to selected approvers.
The automation connection owner uses Basic User plus IRS LEAP Automation.
Dataverse role privileges are cumulative: remove conflicting broad roles from
ordinary-user rehearsal identities. App sharing does not assign data roles.

Prepared code is a workshop candidate, not production authorization evidence.
It treats a caller with the IRS LEAP Automation role (direct or team assignment)
or System Administrator as a trusted writer of workflow fields. The workflow
must authenticate/map the actual selected approval responder; plugin role checks
alone cannot independently prove an approval email was clicked.

An approver assigned to ANY saved request for an employee can request that
employee's annual totals for any selected year. It does not return hidden row
details. This access currently has no automatic expiry; approve the lifetime
and annual-total privacy policy before using real data.

The one native approval service handles first-responder ordering. The guard
rejects stale terminal-state updates but does not establish a durable atomic
outbox or solve every concurrent delivery/read-write race. Ambiguous duplicate
approval dispatch and create-then-wait races require reconciliation. Do not
present the lab as production-ready or exactly-once processing.
